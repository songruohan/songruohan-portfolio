返回全部项目 CASE 05 / INTERNSHIP / AI ASSISTANT

AI 对话助手北京学佳澳软件科技 · 产品实习 / 对话体验与增长改版

DAU 与付费转化增长乏力，表面的问题是“模型不够好”，真正的问题却藏在使用路径里： 新手不会用、长对话上下文丢失、Prompt 质量参差。我从漏斗和数据出发， 用产品手段而不是只靠算法，把这三个问题逐个拆开。

ROLE
产品实习 / 对话体验与增长
TIMELINE
2025.07 — 2025.09
METHOD
漏斗分析 · Prompt 评估 · 版本复盘
RESULT
CTR +14% · 会话量 +26% · 留存 +9%
01

问题

用户不是不愿意用，而是不知道“该怎么用”。

我先把对话产品的链路拆成“进入 → 首次提问 → 多轮对话 → 完成任务 → 付费/复访”， 再结合留存、会话与转化数据定位流失点。问题最终收敛到三个根因：

ROOT CAUSE 01

新手没有可模仿的起点

空白输入框让用户不知道能问什么，首次提问质量低，第一轮就流失。

ROOT CAUSE 02

长对话上下文丢失

多轮之后模型忘记前文，用户需要反复补充背景，体验断裂，任务完成率下降。

ROOT CAUSE 03

Prompt 质量参差

没有统一的输入结构与质量评估口径，同一个需求得到的回答质量不稳定。

ROOT CAUSE 04

模型幻觉带来不信任

回答看起来流畅但事实不可靠，用户一旦踩坑就很难再回来。

02

判断

产品层能解决的，不要都推给算法。

算法优化周期长、成本高，而用户的第一公里体验、上下文组织和输入结构，产品侧可以先做。 我的策略是：先用产品手段降低使用门槛，再建立可量化的评估体系，反向驱动算法迭代。

BEFORE

空白输入框 + 黑盒回答

用户自由输入，系统直接给结果。没有示例、没有结构、没有质量反馈，体验依赖运气。

AFTER

可上手 + 可评估 + 可迭代

快捷指令降低第一步门槛，上下文策略保证多轮连续，评估体系让“回答好不好”可以被讨论和优化。

03

动作

四件事，把体验从“能用”推到“愿意用”。

01 / ONBOARDING

新手前置引导与快捷指令

把高频任务做成可直接点击的模板，用户不需要先学会“怎么问”。

02 / CONTEXT

重构对话上下文管理

明确哪些信息需要保留、何时摘要、何时追问，减少长对话中的背景丢失。

03 / EVAL

Prompt 质量评估体系

从完成率、有效 CTR、用户留存、回答可用性等维度建立可量化的评估口径。

04 / DOC QA

文档解析问答

支持上传文档后直接提问，把“读长文”变成“问重点”，拓展高频使用场景。

同时，我持续跟踪 DAU、会话完成率、转化漏斗与模型调用成本，避免“体验变好但成本失控”。 每次版本迭代都保留前后对比，形成可复盘的结论，而不是只汇报一个漂亮的增幅。

04

结果

体验指标与业务指标同时改善。

+14%对话有效 CTR
+26%总会话量
+22%周活
+9%7 日留存

快捷指令模板带动周活上涨 22%，7 日留存提升 9%。更重要的是，团队第一次有了统一的 “回答质量”讨论语言：哪些问题该被解决、哪些回答算合格、下一版优先改什么。

“AI 产品的体验，不是模型一次回答的惊艳，而是用户第十次回来时仍然信任它。”

如果再做一次，我会补上什么。

  • 分层评估：把“任务完成”拆成可用、准确、可信三层，避免只看 CTR 这类表层指标。
  • 成本前置：在方案阶段就定义 token 成本与响应时延的边界，而不是上线后再压缩。
  • 负反馈闭环：把用户点踩、改写、重复提问变成知识缺口与 Prompt 优化的输入。
